GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。すべてのツール呼び出しやファイル編集を確認し、各差分をインラインでレビューして、変更を受け入れるか拒否できます。エディターを離れずに追加のプロンプトを送り、作業を調整したり拡張したりできます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントを誘導し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用のカスタムエージェントは、ハイコントラストモードを実装中です。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めずに、既存のセッションを誘導して機能を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各ステップ、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中はチャットをスクロールし、ツール操作を確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドなどが表示されます。
3. エージェントがファイルを編集すると、差分がインライン表示されます。
    - 変更を受け入れるには **Keep** を選択します。
    - 変更を元に戻し、別の方法を試すには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、セッション中にエージェントが変更したファイルをすべて確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えも追加します。会話を続けると、エージェントは変更済みのコンポーネント、使用したスタイル、設定をローカルストレージに保存する方法をコンテキストとして保持できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (例: 切り替え UI のリファクタリング方法が異なる場合) は、Chat の入力欄の横にある **Stop** ボタンで停止し、明確な追加プロンプトを送信します。

> [!TIP]
> 作業中のセッションを誘導すると、最初からやり直すより短時間で済みます。追加のプロンプトを使って調整できます (例: 「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正できます (例: 「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」)、範囲を広げることもできます (例: 「両方の切り替えにキーボードショートカットも追加する」)。

## 変更をまとめてレビューする

作業をコミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存など、カスタムエージェントが示したアクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、作業中のセッションを監視して誘導しました。ファイル編集を確認して受け入れるか拒否し、コンテキストを保ったまま追加プロンプトを送り、作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を受け入れるか拒否する。
- 追加プロンプトで作業中のセッションを誘導する。

[次のレッスン][next-lesson]では、アクセシビリティの作業を pull request として公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
